## 2. Detailed Technical Verification Sections (V1 to V11)

### V1 — Read-Only Proof

#### 1. AllowedCommand Enum Definition
The ATA command set is restricted at the type level in `libs/ahci-proto/src/lib.rs`:

```rust
// File: libs/ahci-proto/src/lib.rs:20-26
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
#[repr(u8)]
pub enum AllowedCommand {
    IdentifyDevice = 0xEC,
    ReadDmaExt = 0x25,
    SmartReadData = 0xB0,
}
```

No write ATA commands (such as `0x30` WRITE SECTORS, `0x34` WRITE DMA EXT, `0x35` WRITE DMA EXT QUEUED, `0x61` WRITE FPDMA QUEUED, or `0xCA` WRITE DMA) can be constructed safely through the public API without `unsafe`.

#### 2. MMIO Port Writes: Command Bytes, PxCMD, and PxCI
Every MMIO write in `kernel/src/drivers/ahci.rs` was audited:

- **Command byte construction**:
  - `execute_command(slot, byte_count, build_fis)`: Calls `build_fis`, which only accepts closures invoking `build_h2d_register_fis(AllowedCommand, ...)` or `build_read_dma_ext_fis(...)`.
- **Command Issue Register (`PxCI`, offset `0x38`)**:
  - `kernel/src/drivers/ahci.rs:223`: `mmio_write32(self.reg_base, 0x38, 1u32 << slot);` — exclusively issued inside `execute_command`.
- **Command and Status Register (`PxCMD`, offset `0x18`)**:
  - `stop_engine()` (`lines 136, 144`): Clears `PORT_CMD_ST` (`!0x01`), then clears `PORT_CMD_FRE` (`!0x10`).
  - `bring_up()` (`lines 171, 179`): Sets `PORT_CMD_FRE` (`0x10`), then sets `PORT_CMD_ST` (`0x01`).
  - `execute_command()` error recovery (`lines 251, 255`): Sets `PORT_CMD_FRE`, then sets `PORT_CMD_ST`.
- **Interrupt & Error Clear Registers**:
  - `PxIS` (offset `0x10`): Written with `0xFFFF_FFFF` to clear pending interrupt status bits.
  - `PxSERR` (offset `0x30`): Written with `0xFFFF_FFFF` to clear SATA error diagnostics.

#### 3. BlockDevice Trait Public API
The `BlockDevice` trait in `libs/ahci-proto/src/lib.rs:77-88` is strictly read-only:

```rust
pub trait BlockDevice {
    type Error: core::fmt::Debug;
    fn read_sectors(&mut self, start_lba: u64, count: u32, buf: &mut [u8]) -> Result<(), Self::Error>;
    fn sector_size(&self) -> u32;
    fn total_sectors(&self) -> u64;
}
```

There are no `write_sectors`, `flush`, or `trim` methods in `BlockDevice`.

#### 4. Host Test for Write Opcode Inconstructibility
Currently, `libs/ahci-proto/src/tests.rs` tests valid FIS creation for `IdentifyDevice`, `ReadDmaExt`, and `SmartReadData`, but **lacks an explicit test asserting write opcode rejection**. (Added to P2 fix list).

### V3 — Process Lifecycle & PMM Leak Mechanics

#### 1. Page & Frame Allocation Lifecycle per `exec`

| Step | Action | Virtual Address Range | Frames Allocated | Allocation Source | Deallocation Site |
|---|---|---|:---:|---|---|
| 1 | Segment `PT_LOAD` | `0x0040_0000..0x0040_5000` | N frames | `pmm::alloc_frame()` | `clean_current_process()` via `pmm::free_frame()` |
| 2 | Stack Mapping | `0x7FFF_FFFE_0000..0x7FFF_FFFF_0000` | 4 frames (16 KiB) | `pmm::alloc_frame()` | `clean_current_process()` via `pmm::free_frame()` |
| 3 | Dynamic Heap (`sys_brk`) | `heap_start..heap_current` | M frames | `pmm::alloc_frame()` | `clean_current_process()` via `pmm::free_frame()` |
| 4 | Intermediate Page Tables (PDPT, PD, PT) | Code, Heap, Stack | **0 frames at runtime** | **Pre-allocated during `syscall::init()`** | Persistent across kernel lifetime (never freed) |

#### 2. The "Pre-allocated Intermediate Page Tables" Mechanism Explained
In Milestone 8, executing the first process reported a 6-frame leak (`before=127224, after=127218`, delta = -6 frames = 24 KiB). Those 6 frames were the intermediate page directory tables (PDPT, PD, and PT) allocated by `vmm::get_or_create_next_table` when mapping addresses `0x400000`, `0x800000`, and `0x7FFFFFFF0000`.

In Milestone 9, `vmm::preallocate_user_tables` was introduced and called during kernel boot in `syscall::init()` (`kernel/src/syscall/mod.rs:128-140`):

```rust
crate::mm::vmm::preallocate_user_tables(&[
    0x0040_0000, // User code segment base
    0x0060_0000,
    0x0080_0000, // User heap start
    0x00A0_0000,
    0x00C0_0000,
    0x00E0_0000,
    0x0100_0000,
    0x0120_0000,
    0x0140_0000,
    0x0160_0000,
    loader::USER_STACK_TOP - 0x1000, // User stack top
]);
```

Because these page directory frames are allocated during kernel initialization, the free frame count before process execution (`before`) does not include them. At runtime, `vmm::map_page` finds the page tables already present and allocates only the leaf physical frames. When the process exits, `clean_current_process()` unmaps and frees all leaf frames.

**Critical Architectural Finding:**  
If a binary contains an ELF `PT_LOAD` segment or dynamic mapping at a virtual address outside this pre-allocated whitelist (e.g. at `0x2000_0000` or `0x1000_0000`), `vmm::map_page` will dynamically allocate intermediate PDPT/PD/PT frames from the PMM. Because `clean_current_process()` only tracks and frees leaf frames in `proc.user_pages`, those page directory frames **will permanently leak from the PMM**.

### V4 — File Descriptors & Kernel vs User Space Separation

#### 1. What does `sys_open` return to userland?
`sys_open` (`kernel/src/syscall/mod.rs:371-423`) allocates a descriptor slot from `3..MAX_USER_FDS` (slots 3 to 15) and returns `fd as i64`:

```rust
// File: kernel/src/syscall/mod.rs:395-420
let mut free_fd = None;
unsafe {
    for i in 3..MAX_USER_FDS {
        if !USER_FD_TABLE[i].is_open {
            free_fd = Some(i);
            break;
        }
    }
}
let Some(fd) = free_fd else {
    return -24; // -EMFILE
};

match vfs::open(path) {
    Ok(vfs_fd) => {
        unsafe {
            USER_FD_TABLE[fd] = UserFileDescriptor {
                vfs_fd,
                offset: 0,
                is_open: true,
            };
        }
        fd as i64
    }
    Err(e) => -(e as i64),
}
```

- **Userland FDs**: Small integers `3..15`.
- **Standard Streams**: `0` = stdin, `1` = stdout, `2` = stderr.
- **Kernel-internal ranges**: The `0x0000_0000` (Initramfs), `0x4000_0000` (FAT32), and `0x8000_0000` (ProcFS) descriptor values are **strictly kernel-internal**. They are stored exclusively in `USER_FD_TABLE[fd].vfs_fd` and are never returned to userland.
- **Process FD Table**: Currently implemented as a single global static table (`USER_FD_TABLE: [UserFileDescriptor; MAX_USER_FDS]`), reset upon process spawn/exit. A truly per-process table allocated with the process structure will be implemented in Milestone R5.

### V5 — User Memory Validation Audit & SMAP/SMEP/CR4 State

#### 1. Per-Syscall Pointer Validation Audit

| Syscall | Pointer Arguments | Range & Limit Check | Length Overflow Check | Canonical Check | Page Presence Check | Vulnerability / Bug Identified |
|---|---|:---:|:---:|:---:|:---:|---|
| `sys_read` | `buf: *mut u8`, `count: usize` | `buf < USER_SPACE_LIMIT` | **NO (Overflows)** | Implicit (< 128 TiB) | None | `buf + count > USER_SPACE_LIMIT` can wrap around on integer overflow if `count` is near `u64::MAX`. |
| `sys_write` | `buf: *const u8`, `count: usize` | `buf < USER_SPACE_LIMIT` | **NO (Overflows)** | Implicit (< 128 TiB) | None | Integer overflow: `buf + count` wraps around; unchecked page presence. |
| `sys_open` | `path_ptr: *const u8` | `path_ptr < USER_SPACE_LIMIT` | **NO** | Implicit (< 128 TiB) | None | Reads up to 256 bytes with `*path_ptr.add(len)`. If `path_ptr` is `USER_SPACE_LIMIT - 10`, it reads into kernel space or unmapped memory. |
| `sys_stat` | `path_ptr`, `_statbuf: *mut u8` | Partial on `path_ptr` | **NO** | None | None | **`_statbuf` is completely ignored and unchecked.** |
| `sys_uname` | `buf: *mut UtsName` | `buf < USER_SPACE_LIMIT` | **NO** | Implicit (< 128 TiB) | None | Writes 390 bytes (`sizeof(UtsName)`) without checking if `buf + 390 <= USER_SPACE_LIMIT`. |
| `sys_brk` | `new_brk: u64` | `new_brk < USER_STACK_TOP` | Verified | Implicit | Page mapped on demand | Correctly validates heap boundaries (`heap_start..heap_max`). |

#### 2. CPU Control Register CR4 (SMAP / SMEP State)
- **SMEP (Supervisor Mode Execution Prevention, CR4 bit 20)**: **DISABLED (Not configured)**.
- **SMAP (Supervisor Mode Access Prevention, CR4 bit 21)**: **DISABLED (Not configured)**.
- Grep evidence: `grep -rn "cr4" kernel/src` returned 0 matches.
- Consequence: Kernel ring 0 code can freely execute user memory or read/write user addresses without hardware traps. A bad user pointer will cause a kernel `#PF` panic instead of a gracefully handled `-EFAULT`.

#### 2. Input Devices Post-ExitBootServices on Real Hardware
On real modern x86-64 hardware booted via UEFI:
- **UEFI ExitBootServices() terminates all firmware USB HID drivers.**
- OptiOS currently implements drivers exclusively for:
  1. Legacy 8042 PS/2 Keyboard (`IRQ 1`, I/O ports `0x60`/`0x64`)
  2. Legacy 8042 PS/2 Mouse (`IRQ 12`, I/O ports `0x60`/`0x64`)
  3. 16550 UART Serial Port (COM1, I/O port `0x3F8`)
- **Modern PCs, laptops, and workstations lack physical PS/2 controllers**, and USB legacy emulation is deactivated once UEFI transfers execution to the OS kernel.
- **Result:** On real physical machines, **no keyboard or mouse input works** after boot until an xHCI USB controller driver and USB HID driver are implemented (Milestone R2).

- Milestone 10 Report (line 189): Claims the boot process `"scans the SATA/NVMe storage controllers"`.
- Code Audit:
  - `kernel/src/drivers/pci.rs:58-59`: Class code string mapping only (`(0x01, 0x08) => "Non-Volatile Memory (NVMe)"`).
  - **There is NO NVMe driver in OptiOS.** No PCIe NVMe queue registers, doorbells, or admin commands exist. NVMe support is scheduled for Roadmap Milestone R4.

#### Critical Concurrency & IRQ Findings
1. **Mouse Driver Data Race**: `on_irq12()` runs in interrupt context and mutates `CURRENT_MOUSE` using raw pointers without holding `MOUSE_LOCK`. `get_state()` acquires `MOUSE_LOCK` but fails to disable interrupts (`cli`). If IRQ 12 fires while `get_state()` is copying the structure, a torn read of mouse coordinates and button flags occurs.
2. **Reentrancy Risk in Syscalls**: Syscalls execute in thread context with interrupts enabled (`sti`). If an interrupt handler were ever to invoke logging (`info!`), a deadlock against `SERIAL_LOCK` or `CONSOLE_LOCK` would occur. Hardware ISRs (PIT timer and keyboard) currently obey this rule and perform zero logging.

#### 3. Description of `optios-wm` and the `gui` Command
In `opti-sh` (`kernel/src/shell/mod.rs`), the shell evaluates user input. When the user enters the `gui` command:
- The shell invokes `desktop::launch_desktop_wm()`.
- The system transitions from text console mode to the graphical Desktop Window Manager.
- Window management logic is provided by `libs/wm` (`optios-wm`), featuring draggable window frames, close buttons, minimization, Z-order layering, and double-buffered graphics rendering with mouse cursor tracking.
- Pressing `Esc` exits the window manager and returns the user to the fullscreen text terminal (`opti-sh`).
- **Omission**: While tested in host unit tests (`optios_wm`) and invoked in QEMU automated verification logs, this feature was omitted from the Milestone 10 architectural summary.

#### 3. Does a Source-Agnostic `InputEvent` Abstraction Exist?
**NO.** There is no unified input abstraction in OptiOS today.
- Keyboard events produce `char` values or raw byte sequences pushed into an atomic ring buffer.
- Mouse events produce a dedicated `MouseState` struct (`x, y, btn_left, btn_right, btn_middle`).
- Userland has no standard interface to receive mouse events.
- Milestone R1 will introduce a unified `InputEvent` enum (`KeyPress`, `KeyRelease`, `MouseMove`, `MouseButton`, `Scroll`) as part of the Driver Kit.

## 3. Prioritized Fix List (For Phase 2 Implementation)

The following items are organized strictly by severity. In accordance with Phase 1 directives, **no code changes have been applied**. Each item defines the problem, the minimal proposed fix, and the test required to prove the resolution.

### Priority 0: Security & Data Safety (P0)

#### P0.1: Syscall User Pointer Integer Overflow in `sys_read` and `sys_write`
- **Problem**: `buf as u64 + count as u64 > USER_SPACE_LIMIT` can overflow on 64-bit integer addition if `count` is crafted (e.g. `u64::MAX - 0x1000`), allowing Ring 3 to bypass range checks and access kernel memory.
- **Minimal Fix**: Use `.checked_add()`:
  ```rust
  let end = (buf as u64).checked_add(count as u64).ok_or(Errno::EFAULT)?;
  if end > USER_SPACE_LIMIT {
      return -14; // -EFAULT
  }
  ```
- **Proving Test**: Userland test invoking `sys_read(0, 0x1000 as *mut u8, usize::MAX - 0x1000 + 1)` and asserting `-EFAULT` (-14).

#### P0.2: Missing SMAP/SMEP Hardware Protection in CR4
- **Problem**: CR4 bits 20 (SMEP) and 21 (SMAP) are never set. Ring 0 code can accidentally execute or read/write user memory pages, creating kernel privilege escalation risks.
- **Minimal Fix**: Detect SMEP and SMAP via CPUID (Leaf 7, EBX bits 7 and 20) during `arch::x86_64::init()` and set bits 20 and 21 in CR4.
- **Proving Test**: Automated QEMU boot test reading CR4 and verifying bits 20 and 21 are set.

#### P0.3: ELF Loader Maps All Segments as Writable and Executable (No W^X)
- **Problem**: `kernel/src/syscall/loader.rs` maps every segment with `PRESENT | WRITABLE | USER_ACCESSIBLE`. Code segments are writable, while stack and heap memory are executable.
- **Minimal Fix**: Inspect `seg.flags`:
  - If `(seg.flags & PF_W) == 0`: omit `vmm::flags::WRITABLE`.
  - If `(seg.flags & PF_X) == 0`: include `vmm::flags::NO_EXECUTE`.
- **Proving Test**: Host unit test verifying segment page flags match permissions; QEMU test attempting to write to `.text` segment triggering `#PF`.

#### P0.4: `sys_uname` Unbounded User Buffer Write
- **Problem**: `sys_uname` checks only `buf as u64 >= USER_SPACE_LIMIT`, but writes 390 bytes (`sizeof(UtsName)`). If `buf = USER_SPACE_LIMIT - 100`, it writes 290 bytes into kernel space.
- **Minimal Fix**:
  ```rust
  let end = (buf as u64).checked_add(core::mem::size_of::<UtsName>() as u64).ok_or(Errno::EFAULT)?;
  if end > USER_SPACE_LIMIT {
      return -14;
  }
  ```
- **Proving Test**: Syscall test calling `sys_uname(USER_SPACE_LIMIT - 50)` expecting `-EFAULT`.

#### P0.5: Unbounded Execution Policy across Mounts
- **Problem**: `spawn_user_process_with_args` resolves any path in the VFS. Binaries residing on untrusted external drives (`/mnt/sda1`) can be executed as Ring 3 executables without policy enforcement.
- **Minimal Fix**: Add `MNT_NOEXEC` flag to VFS mount table entries. Configure `/mnt/sda1` with `MNT_NOEXEC` and reject execution with `-EACCES`.
- **Proving Test**: Automated test attempting to execute `/bin/edit` copied to `/mnt/sda1`, asserting exit with permission denied.

### Priority 1: Correctness (P1)

#### P1.1: Missing Automated Port 2 Abort & Second IDENTIFY Selftest
- **Problem**: C0 required a selftest verifying that after a Port 2 command abort, reissuing IDENTIFY on Port 2 returns `TaskFileError` (not `Timeout` or `PortFailed`), while Port 0 continues to function.
- **Minimal Fix**: Implement a dedicated diagnostic selftest in `init_ahci` executed during boot or behind a test flag.
- **Proving Test**: Captured QEMU boot log verifying Port 2 abort, second IDENTIFY returning `TaskFileError`, and Port 0 returning identical Model/Serial/Sectors.

#### P1.2: FAT32 Cyclic Cluster Chain & Out-of-Bounds Detection
- **Problem**: `read_cluster_chain` loops up to 65,536 iterations on circular FAT chains and returns the huge cyclic chain rather than an error. `next_cluster` does not check against volume cluster bounds.
- **Minimal Fix**:
  - In `next_cluster`: verify `cluster < (self.bpb.total_data_clusters + 2)`.
  - In `read_cluster_chain`: maintain a visited cluster bitmap or loop limit that returns `Err(Fat32Error::CyclicClusterChain)`.
- **Proving Test**: Host unit test with crafted circular FAT32 image expecting `Fat32Error::CyclicClusterChain`.

#### P1.3: Hardcoded 512-Byte Sector Size (4Kn Incompatibility)
- **Problem**: AHCI driver, partition table parser, and FAT32 crate hardcode 512 bytes per sector. 4Kn native enterprise disks fail to mount or read.
- **Minimal Fix**: Read logical sector size from ATA IDENTIFY (words 106 and 117); parameterize `BlockDevice::sector_size()` across all layers.
- **Proving Test**: Host unit test mounting a 4096-byte sector FAT32 volume.

#### P1.4: GPT LBA Bounds & Partition Array Multiplication Overflow
- **Problem**: `libs/partition-table` does not check if `start_lba <= end_lba` or verify bounds against `first_usable_lba` / `last_usable_lba`. `num_entries * entry_size` uses unverified multiplication.
- **Minimal Fix**: Use `.checked_mul()`; validate `start_lba >= first_usable_lba && end_lba <= last_usable_lba && start_lba <= end_lba`.
- **Proving Test**: Unit test with hostile partition table entries expecting `PartitionError::InvalidPartitionBounds`.

#### P1.5: PMM Leak on ELF Executables Outside Preallocated Virtual Ranges
- **Problem**: If an ELF binary maps virtual pages outside `0x400000`, `0x800000`, and `0x7FFFFFFF0000`, new intermediate PT frames are allocated from the PMM and never freed on process termination.
- **Minimal Fix**: Track all allocated page directory frames in `ProcessMemory` and unmap/free them in `clean_current_process()`, or isolate processes within separate PML4 page table structures.
- **Proving Test**: Spawning a test ELF located at `0x2000_0000` 50 times in succession, asserting free PMM frames remain identical.

#### P1.6: QEMU Boot Order Conflict on SATA ESP Disk Attachment
- **Problem**: When a test SATA disk containing a FAT32 ESP without `BOOTX64.EFI` is attached to SATA Port 0, OVMF attempts to boot it before the CD-ROM, dropping into the EFI Shell unless `bootindex=1` or `-boot order=d` is specified.
- **Minimal Fix**: Explicitly specify `bootindex=1` for the boot media or `-boot order=d` in `scripts/run.sh`.
- **Proving Test**: Automated QEMU boot test running to completion without falling into the EFI Shell.

#### P1.7: PS/2 Mouse Data Race Between IRQ 12 ISR and `get_state()`
- **Problem**: `on_irq12()` mutates `CURRENT_MOUSE` without holding `MOUSE_LOCK`, while `get_state()` acquires `MOUSE_LOCK` without disabling interrupts (`cli`).
- **Minimal Fix**: Make `MOUSE_LOCK` IRQ-safe by executing `cli` before acquiring and restoring flags on release, or update coordinates atomically.
- **Proving Test**: Host concurrency test simulating asynchronous interrupt state updates against reader threads.
